## 1. 两报告冲突裁定

### 1.1 事实层无分歧

两报告对以下事实**独立复核一致**，PI 全部采纳：

- 520 对（probe40/train120/val60/test300，real=0），manifest 哈希/行数/质量门逐项一致、seed=0 字节级可重建；
- 数据工程师复核（审计 §1–§3）：train/test 模板骨架 100% 重合（"未见模板"仅后缀）、8 个实体全共享、≥15 组跨 split 逐字相同文档（含 train↔test 整对泄漏）、18 条 `must_flip=true` 且候选相同的退化对（test 7 条）、cluster bootstrap 退化为逐对 i.i.d.（300 唯一簇、真实独立模板仅 8）；
- 科学家复核（§0.1）：逐行对照给出退化对可追溯 pair_id、确认簇口径歧义、确认 P3 主终点 22 run 无一在 test 评测。

**裁定**：数据工程师的"否（不达标）"与科学家的"可发（限边界/实证）"并非事实冲突，而是**问题性质判断的分歧**。PI 的裁定基于一个区分：

### 1.2 关键区分：外部效度缺口 vs 内部正确性缺陷

- **外部效度缺口**（可披露为限制，不强制修复）：real=0、仅 MVP 等深对正向、8 个基础模板、无外部基准。这些限制**缩小结论适用范围**，但不会让已报告的数值变成错误的。科学家"披露即可"的判断在这类问题上成立。
- **内部正确性缺陷**（不可仅披露，投稿前必须修）：退化对（`candidate_A==candidate_B` 却 `must_flip=true`，物理上不可翻转）污染 flip/dual/E_CF 分母；跨 split 逐字文档泄漏污染 test 主终点与 P2 held-out；bootstrap 簇退化使 CI 系统性偏窄、显著性被夸大；flip 分母口径 394（代码）vs 457（冻结配置 `flip_denominator_excludes:[F5]`）冲突。这些**会让已声称的贡献(1)(2) 指标本身失真**——披露"数据有泄漏"不能让一个被泄漏抬高的 CI 重新可信。数据工程师的底线判断在这类问题上成立。

> **PI 结论**：**当前数据"可投边界/实证研究"这一方向成立（科学家对），但在修复一组正确性缺陷之前"现在就投"不成立（数据工程师对）**。两报告各自在适用范围内正确；分歧由上述区分消解。**暂缓投递，先修正确性，再以边界/实证研究定位投递。**

### 1.3 对论文现状的额外裁定

- 贡献(1)(2) 强形式、边界/实证定位的**措辞门槛本身合规**（见 final_signoff/contribution2_final_form 签 off）——但**证据基础的统计可信度被数据缺陷削弱**。修复后重跑 P1/P2 是为了让已签 off 的贡献(1)(2) 建立在干净数据上；这不是推翻此前签 off，而是兑现其"诚实披露 + 证据强度保留"的前提。
- 22 run 无一在 test 评测：对边界/实证研究**不构成投稿障碍**（主终点属贡献(3)，已 withheld）；但它意味着贡献(1) 的"独立测试集"证据实际来自 val/train，**正是科学家判定"限定范围"的原因**——修复后在干净 test 上补一次 gap 核验（见 M8′）可强化贡献(1)，属增强项非阻断项。

## 2. P3 指令：暂停正式 run，并行实现与数据修复

> **明确裁定：立即暂停 P3 所有在封存 test 上的正式 run；允许工程师继续实现前置（commit 885a36a 的 P3_gpu.py）与非 test 烟测；数据修复并重建后再重启 P3。**

理由：

1. P3 主终点在 test 上（`p3_task_plan §4`），而 test 含 7 条退化对、≥4 条 train↔test 泄漏、仅 8 模板结构、bootstrap 簇退化——在污染 test 上跑出的主终点 CI **既不可发表也不可信**，且 δ 网格负值预警使正结果概率本就低（`p3_resource_estimate §5`）。
2. 封存集纪律：一旦用被污染的 test 跑过主终点并据以调整，封存性即被消耗；在修复前跑等于浪费唯一一次封存评测机会。
3. 成本：P3 探路 2.5–3h、全量 5–7h 串行；在坏数据上投入是无谓算力。

**允许继续**：`P3_gpu.py` 入口、可微 `torch_candidate_logits`、预算配平、新 commit 纳入跑分代码（避免 R1 重演）、以及 `reports/_non_authoritative/` 下的非 test 烟测门（`p3_smoke_cflite_seed0`）——这些不读封存 test，可并行推进，不浪费时间。

**重启条件**：M1/M2/M6/M7（正确性口径）完成、数据重建 + manifest 更新、P1/P2 在干净数据上重跑确认 gap/机制仍成立后，按 `p3_task_plan` 的门控串行启动 P3，且主终点的聚类单元口径须用新增版本文件冻结（见 M6′）。

### 3.3 PI 对 flip 分母口径的直接裁定（M7′）

- 事实：冻结配置 `configs/protocol.yaml:43 flip_denominator_excludes: [F5]` → 按字面 F6 应计入，分母 = F1+F2+F3+F4+F6 = 394+63 = **457**；代码实现把 F6 也排除（`must_flip=false`），分母 = **394**。
- `docs/protocol.md §3.2` 与实验设计表 E3 均只明确"F5 不入翻转分母"，未说明 F6；F6 是"长度/位置控制"，语义上答案不应翻转，排除有合理性，但**与冻结配置字面冲突**。
- **裁定：维持排除 F5 与 F6（分母口径 394）**，理由是 F6 作为长度/位置控制语义上非翻转；但**必须由有权限角色以新增版本文件把 `flip_denominator_excludes` 明确为 `[F5, F6]`** 并说明理由，消除配置与代码冲突。PI 不回写 `configs/protocol.yaml`。修复退化对后分母相应重算并写入新版本文件。

### 3.4 修复后重跑范围

M1/M2 改变 `cf_pairs.jsonl` 内容与哈希 → 所有基于旧数据的 run 溯源过期：

- **E0**：数据与语义无关，旧门可保留；重建后快速复验一次即可（低成本）。
- **P1（E1）**：**必须重跑**（≥3 seed）——退化对/泄漏直接影响 gap、dual、flip 与 kd 三 seed 结论；且应在干净 test 上补一次 gap 核验以强化贡献(1)（M8′，增强项）。
- **P2（E2）**：**必须重跑**（三 seed）——held-out 与 train 的文档泄漏可能抬高机制表观成绩；U 选择基于 train 数据，须在干净数据上重选。
- **P3（E3）**：修复后按 §2 重启，主终点聚类口径用 M6′ 新版本文件冻结。
- P4/P5：维持 NO-GO / 暂缓，待上述闭环。

### 3.5 是否改冻结判据

- `phase1_benchmark_decision.yaml`、`phase3_method_decision.yaml`、v2.1/v2.2 loss config、`configs/protocol.yaml` 的**判据与数值均不改**。
- M6′（聚类口径）、M7′（flip 分母）属统计口径澄清，**由有 prereg 权限角色新增版本文件**（如 `configs/prereg/stats_convention_v2.3.yaml`），PI 不自行回写任何已冻结文件、不写 `src/**`。

## 4. 论文与投稿时机裁决

1. **定位**：维持 empirical/boundary study 成立（贡献(1) 全 + 贡献(2) 强形式，贡献(3) withheld）——数据修复不改变定位，只提升证据可信度。
2. **数据限制写入**：**必须**在正文 `main.tex` 与 `notes.md` 写清：(a) 合成域、模板多样性有限；(b) 正向证据仅 MVP 等深对；(c) real=0 / 缺外部锚点（若 M4 未做）；(d) 空翻转与泄漏已修复及修复前后口径；(e) bootstrap 簇口径与 pair-level 敏感性；(f) flip 分母口径 394（排除 F5+F6）。修复项完成后同步更新相应 limitation 措辞。
3. **投递时机**：**暂缓**——待 §3.1 正确性项闭环 + §3.4 P1/P2 重跑后再投。现状稿件不得立即投稿。
4. **对外主张强度边界**：贡献(1) 限定"该受控合成域、MVP 对、已测 mapper 范围内"；贡献(2) 强形式限定 MVP 等深对、局部恒等式、Oracle 离线，禁 "across model pairs / causal / sole cause"，强制披露 F4/F6 与第 5 单元漂移；贡献(3) withheld，禁任何方法增益/跨模型/系统收益措辞。

## 5. 仍需人工（真实 PI）决策的事项

1. **真实文档来源与许可风险（M4）**：80–150 对真实文档的采集渠道、授权合规、人工核验人日（5–10）——硬约束要求真实数据须记录来源/许可并经 PI 裁决后方可进入主实验；是否投入由真实 PI 拍板。
2. **额外算力/人日投入**：数据+统计侧补足 7–11 人日（不含真实文档），含真实文档 12–20 人日；P1/P2 重跑 + P3 重启的 GPU 机时——是否批准该量级投入。
3. **投递时机**：暂缓后何时投（修复正确性即投 vs 连 M3/M4 一起补齐再投更强版本）；是否等 P3 主终点结果（负值预警使该路径成功率低）。
4. **是否继续 P3 方法层路线**：鉴于 δ 网格负值 + 数据缺陷，是否投入 P3，还是以边界/实证研究收口（本裁决已暂停 P3 正式 run，重启与否待人工确认）。

## 6. 结论与执行顺序

- **冲突裁定**：数据事实无分歧；可投边界/实证研究的判断成立，但正确性缺陷必须先修 → **暂缓投递**。
- **P3**：暂停正式 test run；允许实现/烟测并行；数据修复 + 重建 + P1/P2 重跑后再重启。
- **修复优先级**：P0 正确性（M1、M2、M6′、M7′）→ P1 效度（M3、M4、M5、引用）→ 重跑 P1/P2 →（可选）重启 P3 → 投递。
- **冻结判据**：全部不改；M6′/M7′ 由有权限角色新增版本文件澄清口径。
- **定位**：维持 empirical/boundary study；贡献(3) 绝不升格；数据限制写入正文/notes。
