## 0. 与已 NO-Go 任务的区分（关键）

> **本任务 ≠ `final_implementation_plan.md` 中 NO-Go 的 ARC/HellaSwag 锚点。** 锚点是"再加一个仍只是 exploratory 的旁证"（边际收益近零）；本 2×2 是**直接检验论文核心因果主张**的受控交叉对照，科学性质完全不同。

独立审稿报告（`independent_research_and_manuscript_review_2026-11-23.md`）把本论文的核心障碍定位为：
- 主张表第 14 行："数据缺陷制造了假阳性，修复足以导致翻转"——**"现有对照无法确定翻转由哪项变更造成"**；
- 意见 1（**必改**）："若保留『缺陷导致翻转』的主张，需要固定其余条件的逐项干预对照，或**训练集版本 × 评估集版本的交叉对照**"（`refine-logs/EXPERIMENT_PLAN.md` 的 2×2 正是此设计）；
- 复审条件："以现有证据完成一版**描述性的**负面结果稿有可行路径……优先重写因果措辞"。

当前 main.tex 仍用因果措辞（line 67 "data defects manufactured a false improvement"、line 361 "defects directly produced the spurious positive findings"）。因此这批 GPU 任务的去留，取决于论文是否保留因果主张——这是本次裁决的核心权衡。

## 1. 执行裁定：有条件 GO（投稿前可选增强，PI 强烈建议）

> **裁定：GO（有条件）——执行 2×2 交叉对照，定位为"投稿前可选增强"，但鉴于它直接解决 TMLR 审稿的首要障碍，PI 强烈建议执行。以新增 `configs/prereg/gpu_followup_v2.7.yaml` 先冻后跑为前提。**

### 1.1 科学收益 vs 成本权衡

**收益（实质）**：
1. **直击首要审稿障碍**：审稿"证据充分性判为否"的核心就是因果归因无对照；2×2 把"校准语料版本"与"验证语料版本"对翻转的影响**分离**，要么支撑因果主张（固定 val 换 calib 仍翻转），要么诚实地把结论限定为版本敏感性——两种结果都让论文在 TMLR 审稿下更站得住。
2. **强化论文最有价值的卖点**：本文的核心贡献就是"数据缺陷如何制造虚假发现"；2×2 若显示校准版本效应，直接把这一定性从"推断"升级为"受控观察"。
3. **诚实性收益**：方案 §2 已预承诺如实报告"四格只能识别整体版本切换、非单项缺陷因果"——即便结果为混合，也提升论文的严谨度，与负面/边界研究的诚实定位一致。

**成本（可控但非零）**：
- 1–2 单卡 GPU 小时（12 格 + 冒烟 + 排查缓冲），当前 GPU 空闲，无争用；
- 新审计入口实现（显式接收两份 train/两份 val，不调用会重建数据的 `P1_gpu.py`）——这是主要工程成本；
- CPU 侧导出 6 组 train/6 组 val（旧 458de18 / 新 efc3ba3 生成器）；
- **代价**：补结果后论文要改、**重新触发 P5 签off 与审稿**（见 §1.2）。

净判断：收益（解决首要审稿障碍 + 强化核心卖点）显著大于成本（1–2 GPU h + 一次重审），故 GO。

### 1.2 对 P5 的影响（诚实告知）

- **这批任务会重新触发 P5 签off 与审稿**：论文需补四格结果、可能调整因果/描述措辞（line 67/361）、需按方案 §2 更新统计口径说明；写作者改稿后必须重走审稿一致性核验（新的 compliance note）与 PI 最终签off。**不再是"R1–R5 收尾完即可投"的状态。**
- **它是"投稿前可选增强"而非绝对必须**：审稿复审条件明确"以现有证据完成一版描述性负面结果稿有可行路径"——若真实 PI 选择最快投递，可不做本实验，但必须**撤下因果措辞、改为描述性主张**（line 67/361 改成"审计发现缺陷；重建后结论翻转"），并在 cover letter 说明。
- **二选一，不可兼得**：不能既不做实验、又保留"缺陷制造假发现"的因果强主张——那正是审稿的"必改"障碍。

### 1.3 预注册纪律

- `refine-logs/EXPERIMENT_PLAN.md` 是**实验方案（plan）**，不是已冻结判据；其本身注明"原测试计划有事先记录，但失败边界问题在结果产出后重述"——不足以作为冻结判据。
- **裁定：由 PI 新增 `configs/prereg/gpu_followup_v2.7.yaml`（`frozen_at: protocol-v2.7`）先冻后跑**，写入：四格定义、L 指标（Self−Joint dual，百分点）、两项预固定对比（固定 val 换 calib / 固定 mapper 换 val）、模板族 bootstrap 主 + pair 敏感性 + exploratory(<24 族)、12 格 seed 0/1/2、归因边界（只识别整体版本切换、不声称单项因果）、不恢复贡献/不重算主终点、forbidden_after_freeze。**不回写 v2.1–v2.6 或任何旧文件。**
- 冻结完成前不得启动任何 A00–A11 run。

## 3. 结果判读与论文边界（预承诺，写入 v2.7）

- 主指标 `L = Self dual − Joint dual`（百分点），全部 60 对 + F1–F4 + coverage 联合报告。
- 两项预固定对比：①固定 val 换 calib（旧 val 上 A10−A00、修复 val 上 A11−A01）→ 校准版本效应；②固定 mapper 换 val（A01−A00、A11−A10）→ 评估集构成敏感性。
- **归因边界（强制）**：四格识别"两个数据版本整体切换"的影响；**不得**把变化归因于去重/退化对/模板重叠中的单项（那需单缺陷因果实验，见 §4）。
- **因果措辞规则**：若固定 val 换 calib 的差异持续且方向稳健 → 论文可保留"校准语料版本影响迁移判断"的受控观察；否则一律降级为描述性"重建后翻转"，撤 line 67/361 的因果强措辞。
- 不恢复贡献(1)(2)(3)、不重算主终点、不碰合成封存 test、不与锚点混算。

## 4. 首轮后可选项顺位意见

- **候选整串评分（方案 §4 首选）**：**推迟到本文投稿后**。它是对"首 token vs 整串评分"读数稳健性的补充，审稿意见 2 也要求说明 g/dual 是首 token 代理——但这是措辞澄清（正文说明即可），不必本轮新增前向。投稿后若投稿意见要求，再做 seed0→1/2 的整串核验。
- **单缺陷因果实验（方案 §4 次选）**：**本轮不做、且不建议在本文做**。它需要注入特定缺陷的受控干预，成本高、且属"明确因果主张"才需要的证据；本文已按 §3 预承诺把归因限定到"整体版本切换"，不需要单项因果。
- 两者均不属投稿前门槛；本轮只做 2×2 首轮。
