## 1. M4 真实文档采集方案

### 1.1 PI 对来源优先级与许可类型的裁定

依据采集计划 §2 四类候选，PI 裁定优先级（先低风险、可核验、可再分发）：

| 优先级 | 来源类别 | PI 裁定 | 理由与风险边界 |
|---|---|---|---|
| **1（首选）** | 公共领域 / 政府公开报告、公告文本 | **优先采用** | 版权状态相对清晰（多为公共领域或明确再使用条款），事实明确、易核验；风险边界：须逐份确认发布机构版权声明、发布日期、是否含个人数据（含个人信息者剔除或脱敏）。 |
| **2（次选）** | Wikipedia / Wikidata 派生文本 | **条件接受** | 事实句丰富、易构造实体替换；但多为 **CC BY-SA**，须履行署名 + 相同方式共享义务。**PI 裁定：接受 CC BY-SA 与 CC0/CC BY，前提是可再分发衍生数据且能落实署名/共享声明**；若某页面许可不明或禁止再分发 → 不纳入。 |
| **3（限制）** | 已有学术基准语料 | **仅作锚点用途，不进入 real split 做反事实改写** | 多数仅授权研究用途、禁止再分发或需签协议（中—高风险）；作为外部锚点按各自 license 合规使用，不作为可改写发布的 real 文档源。若许可明确允许改写+再分发方可升级为 real 源。 |
| **4（不采用）** | 项目内部已授权语料 | **本轮不采用** | 内部授权范围不透明，且可能涉及内部数据合规；除非提供明确授权文件并 PI 单独裁决，否则不用。 |

**可接受的许可类型（PI 白名单）**：公共领域、CC0、CC BY、CC BY-SA（落实署名+SA 义务）、明确允许改写与再分发的政府/官方开放条款。**不可接受**：许可不明、禁止再分发、仅限研究且不允许发布衍生、需签署未获得协议、含未脱敏个人数据的文本。

**风险边界**：任何来源在"来源 URL/标识、版本/日期、许可证原文、原始文件 sha256、处理脚本 commit"五项登记齐全并经合规核验前，**不得进入主实验**；许可不清 → 该来源整批剔除，不勉强凑数。

### 1.2 规模与 split 隔离

- **规模**：80–150 对真实反事实文档对（协议 §3.3 建议下限）；建议目标 **100 对**以留抽检返工余量。
- **独立 `real` split**：新建 `data/tasks/cf_pairs_real.jsonl`（或等价文件），`split="real"`；与合成 probe/train/val/test 完全隔离；**不得并入 test、不得参与任何已冻结主终点**。
- **隔离纪律**（承接采集计划 §3.5）：按来源文档分组切分，同一原文/实体不得跨 real 内部评测子集；记录来源/许可/编辑类型/抽检字段。

### 1.3 执行方、验收标准、排期

- **执行方**：数据工程师（采集、构造、入库、manifest/数据卡更新）；**PI + 合规角色**负责许可预评估与入主实验前裁决；科学家协助反事实编辑语义校验。
- **验收标准**：
  1. 80–150 对，`real` split，schema 与合成数据一致并含来源/许可/版本/日期/hash/commit/编辑类型/抽检字段；
  2. 每对来源五项登记齐全、许可属 §1.1 白名单、无个人数据风险；
  3. `must_flip` 语义正确、候选相异（F5 除外）、F5 负控/F6 条件扰动标注正确（复用 M1 退化对断言）；
  4. 双人标签校验 + ≥20% 抽检通过并留痕；
  5. manifest 更新（新增 real sizes/by_slice/hash）+ 数据卡（`docs/data/`）覆盖真实来源；
  6. **PI 合规签off 后方可进入主实验**。
- **排期**：5–10 人日，按采集计划 §4——来源筛选与许可预评估 1–2（**关键路径，立即启动**）、抽取与构造 2–4、双人校验+抽检 1–2、入库 0.5–1。许可预评估为关键路径，建议最先启动。

## 2. 外部锚点方案

### 2.1 PI 裁定：锚点用途与基准选择

- **目的（明确，防止重跑主终点）**：检验"affine 迁移失败边界"是否**跨数据源成立**，并为自建 `E_CF` 提供与标准 QA 的外部锚点（回应弱点"E_CF 下降对应什么真实能力"）。**不是**重跑或替换 V2.0 主终点，也不是贡献(3) 证据。
- **基准选择（考虑许可与可比性）**：

| 基准 | 用途 | 许可/可比性 | PI 裁定 |
|---|---|---|---|
| **SQuAD（抽取式 QA）** | 事实定位/答案跨度，最接近"文档事实编辑"语义 | 许可相对宽松（常见 CC BY-SA 4.0）；事实句与实体可替换，可比性高 | **首选锚点**（注意许可义务） |
| **ARC（选择题科学 QA）** | 两选一/多选一候选结构与本项目 A/B 口径相近 | 多为研究用途许可，多数可合规用于评测（不改写发布） | **次选锚点**（仅评测，不发布衍生） |
| **HellaSwag（常识补全）** | 通用语言理解旁证 | 许可多研究用途 | **可选补充**，可比性较低（非文档事实编辑），优先级最低 |

PI 裁定：**以 SQuAD（事实/抽取）为主锚点、ARC（候选结构与 A/B 相近）为辅**；HellaSwag 作为可选常识旁证。**仅按各基准自身 license 合规用于评测，不改写/再发布其语料**（与 §1.1 "学术基准仅作锚点"一致）。若某基准许可不允许当前用途 → 换用次选，不强用。

### 2.2 规模、判据、执行方、排期

- **规模**：每个选定基准取合规子集（如 SQuAD dev 子集若干条、ARC 若干条），量级以能在 1–2 人日内完成评测为准；具体条数由数据工程师按可比性抽取并记录。
- **判据（外部效度观察，非主终点）**：
  - 报告 Joint（affine）与 kd_only 在标准 QA 上的常规质量（EM/Accuracy）与"答案对编辑的响应"；
  - 检验"迁移失败边界"是否跨源复现：即 affine Joint 是否在真实/标准 QA 上同样质量坍塌、kd_only 是否同样保持 utility；
  - **预承诺**：锚点结果只用于支持/削弱"失败边界的外部效度"，**不作为贡献(1)(2) 恢复的依据**（见 §3）。
- **执行方**：数据工程师（数据/许可）+ 工程师（评测 run）；审稿人复核统计。
- **排期**：与 M4 并行，1–2 人日 + 数小时评测。

### 2.3 是否新增 version prereg 文件

- **需要**。外部锚点与 real split 的评测口径（数据划分、比较对象、判据、是否 exploratory）属新规则，**不得回写**任何已冻结判据。
- **裁定**：由 **PI 在锚点/real run 启动前新增** `configs/prereg/external_validity_v2.4.yaml`（`frozen_at: protocol-v2.4`），写明：real split 与主终点隔离声明、锚点比较对象与判据、v2.3 聚类单元对真实文档的定义（按 §4.3）、预承诺的"不恢复贡献"规则、exploratory 处理。说明新增理由并引用本计划。**先冻结后跑**。

## 3. 对现有结论的影响边界 + 预承诺规则

### 3.1 影响边界（明确）

M4/锚点补齐后：

- **可写**（外部效度增强）：可在论文新增"真实文档/外部基准上的外部效度"段落，如实报告失败边界是否在 real/锚点上复现或减弱。
- **禁写**：不得据 real/锚点恢复贡献(1) 的 "reproducible utility-preserving gap"、贡献(2) 机制定位、贡献(3) 方法增益；不得写"跨模型/普遍失真/真实世界泛化"的正面主张。定位仍为失败边界 + 数据教训的负面/实证研究。
- 贡献清单沿用 `final_boundary_study_signoff §3.2` 的可写/禁写，外部效度结果按此归类。

### 3.2 预承诺规则（防事后择支，防 real/锚点与合成域相反时反转叙事）

**在看到 real/锚点结果前**锁定判读：

- **若 real/锚点复现合成域结论**（affine 迁移失败、kd 保持 utility）——强化"失败边界具有跨数据源外部效度"，按负面结果论文写。
- **若 real/锚点与合成域相反**（如 affine 在真实文档上不坍塌、或 gap 消失）——**不得据此反转论文为正面贡献论文**；应如实报告"失败边界依赖数据构造/合成域条件"，作为**适用边界进一步收窄**的证据，贡献(1)(2)(3) 状态**一律不变**。
- **若结果混合/样本不足**（real 量小、exploratory）——如实披露为探索性，不作强推断，维持现状定位。
- **任何情形下**，均不得因 real/锚点结果调整已撤回的贡献状态、不得事后修改冻结判据、不得挑选有利子集报告。

## 4. 是否需要重跑实验

### 4.1 性质裁定：新增外部验证，不替换合成主实验

- real split 与锚点是**新增外部验证臂**，**不是**替换合成 P0–P3；已完成的干净数据 E0/P1（affine + kd）结果保留为合成域主证据，不重跑。
- 不重跑任何已冻结主终点；不恢复 P2/P3/P4。

### 4.2 新 run（仅外部验证臂）

若需产出 real/锚点结果，新增 run（由工程师执行，v2.4 冻结后启动）：

- **run_id 命名**：`eval_real_affine_seed{0,1,2}`、`eval_real_kd_seed{0,1,2}`（真实文档臂）；`anchor_{squad|arc}_{affine|kd}_seed0`（锚点臂，单 seed 足够——锚点为外部效度观察，非主终点）。
- **种子数**：real 臂 ≥3 seed（seeds 0/1/2，遵循 min_training_seeds=3 纪律）；锚点臂 seed0。
- **统计口径**：沿用 v2.3 原则——主聚类单元按真实文档的**来源文档/主题簇**（real split 每条真实来源为簇）而非逐对，附 pair-level 敏感性；簇数<24 则标 `exploratory=true`；flip 分母按 real 实际切片重算（v2.4 明确）。真实文档"模板族"概念不适用，改以来源文档/主题为簇，**由 v2.4 冻结定义**。
- **配置**：沿用 repro 权威代码（commit 在 HEAD 历史、跑分代码与 HEAD 一致）、bf16/sdpa、`zero_re_prefill=true`、git_hash 入 config；新 commit 纳入任何新增评测代码（避免 R1 重演）。
- **预算与排期**：real 臂 6 run（纯评测，约 5–7 min/run）+ 锚点臂 2–4 run，远小于 P3；串行（并发惩罚）；合计 GPU <1 h，含聚合/审计 <0.5 人日。
