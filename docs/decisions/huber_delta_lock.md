## 2. 口径裁定：「不劣于 kd_only」是**硬护栏**，不引入容差

冻结规则第 2 条为"dual_correct 与 flip_consistency **不劣于** kd_only"。并行实例提出：若解释为带容差的软护栏（如比照 `transfer_health` 的 `dual_drop<0.2`），则 δ=1.0 会因 E_CF 显著最优而胜出。**PI 明确否决该软护栏解释，裁定为硬护栏（hard guardrail）**，理由如下：

1. **字面语义**："不劣于（not worse than / non-inferior）"是门槛式表述，意为"不得低于参照"，包含相等（δ=0.5 的 dual=0.70、flip=1.0 恰好等于 kd_only，判为满足）。引入 0.05 或 0.2 的容差即变成"可以略劣"，与字面冲突。
2. **不得事后改判据（Hard No）**：`phase3_loss_config_v2.1.yaml` 未预置任何 dual/flip 容差参数。在看到网格结果后临时引入容差以改变胜出者，属于按结果改判据语义，直接触犯"判据先写后跑 / 不得按测试结果调阈值"的硬约束（§4.5、`forbidden_on_test`）。
3. **协议一级原则**：`docs/protocol.md §4.1` 与 README 明确"低 E_CF 单独不足以证明信息正确利用，必须与 dual_correct / flip_consistency / coverage / info_gap 联合报告；单独 E_CF 下降不构成改善"。δ=1.0 恰是"E_CF 大幅下降但 dual 跌破护栏"的退化候选——若选它，等于用单一指标覆盖联合报告护栏，违背研究主线设计哲学。
4. **规则整体意图**：规则第 2、3 条的立法目的正是防止"低 E_CF 但质量退化"的退化解。将其降格为软参考会架空这两条，使"优先级"退化为"只看第 1 条"。

**执行语义澄清（消除误读）**："固定优先级、逐条比较"的正确落地是**护栏 + 目标的两阶段约束**——先以第 2、3 条硬护栏筛除不合格候选（可行性约束），再在合格候选中按第 1 条选 val E_CF 最小者（优化目标）。"第 1 条优先"不等于"可为第 1 条牺牲第 2 条"。

## 3. 最终值锁定：δ = 0.5

按上述硬护栏口径逐条执行：

- δ=1.0：E_CF 最小，但 dual=0.65 < 0.70，**违反硬护栏第 2 条 → 否决**（无论 E_CF 低多少）。
- δ=2.0：dual=0.533 < 0.70 且 flip=0.958 < 1.0，双重违反第 2 条，E_CF 亦非最小 → 否决。
- δ=0.5：dual=0.70 ≥ 0.70、flip=1.0 ≥ 1.0、普通 QA 不变 → **唯一同时满足第 2、3 条的候选**；在合格集合内按第 1 条选出。

**PI 裁决：最终 δ = 0.5（logit 单位）**，依据 `phase3_loss_config_v2.1.yaml final_value_rule`（"若网格最优偏离标称 1.0，以网格结果为准"）。该值**仅在验证集锁定**；封存测试期间不得再调整、不得重跑网格、不得改变 L_CF 的 Self 有效掩码（`forbidden_on_test`）。网格完整结果、split id 与搜索成本须随 P3 run config 落盘，交审稿人复核。

## 4. 如实记录的不利事实与 caveat（不掩盖）

1. **本网格内无任何 δ 使主终点方向为正**：三个候选的 joint E_CF（2.7496 / 1.5968 / 2.7625）**全部高于 kd_only（0.735）**。即在此验证集网格中，没有任何 δ 让 CF-RCT-lite 优于 kd_only。这是真实结果，如实记录；它构成 P3 方法的重大风险预警——若封存测试延续该方向，按 `protocol.md §8`"CF 方法不优于 KD → 方法贡献降级"分支处理。
2. **预算不对等 caveat**：δ 网格为 60 对 / 3 epoch，kd_only 参照为 120 对 / 8 epoch，二者非同预算；"不劣于 kd_only" 的双边比较仅供初筛。该 caveat 双向作用——既提示 δ=0.5 的 dual=0.70 "恰好压线"满足不稳健，也提示 δ=1.0 的 dual 下降未必稳固；**但不得以 caveat 为由放宽硬护栏或改选 δ=1.0**。审稿人须知悉此压线性。
3. **git 来源 caveat**：网格 run 的 `git_hash` 为 `ff578b5`（δ=1.0）、`a04990d`（δ=2.0），系 run 启动时刻的 HEAD，跑分代码路径与 `458de18` 一致。按 `engineer_status.md §7` 的"ancestry + 跑分代码一致性"口径审计，勿用严格 hash==HEAD 相等。该项属 `p1_go_no_go.md` R1 闭环待办，不改变本 δ 锁定裁决。
4. **非劣门槛为压线满足**：δ=0.5 的 dual/flip 恰等于参照值，非劣效的统计证据较弱（受 caveat 2 影响）。这是选 δ=0.5 的已知弱点，须在 P3 结果与审稿中如实披露，不得包装为稳健优势。

## 7. 结论摘要

- **「不劣于」口径 = 硬护栏，不引入容差**（事后加容差=改判据，Hard No；且违背联合报告一级原则）。
- **最终锁定 δ = 0.5**（唯一满足硬护栏第 2、3 条的候选；δ=1.0 因 dual 0.65<0.70 被否决，δ=2.0 双重劣化）。
- **仅验证集锁定，封存测试前不得再调**。
- **不利事实如实记录**：三 δ 的 val E_CF 均高于 kd_only（本网格无正方向）；预算不对等、δ=0.5 压线非劣、git 来源 caveat 均已披露。
- **前置 (a) 实质满足、形式 pending；P3 维持 NO-GO**，仍待 R1/R3/R4、P2、审稿第 2 轮与形式闭环。
