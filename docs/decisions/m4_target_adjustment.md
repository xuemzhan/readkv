## 1. M4 结局选择：受阻披露 real=0

> **裁定：在预承诺三结局（完成 / 延后 / 受阻披露 real=0）中，正式选择「受阻披露 real=0」。**

理由（承接科学家评估与 m4_blocker_ruling §2 触发条件）：

1. **源闸门失败**：唯一许可干净（CC0）可下载候选 SciTSR-pd 语义不适配——F2 推理链、F3 方向/否定不可构造，F1/F4/F5 仅有限支撑，F6 存在位置-事实绑定缺陷；其余高适配文本源全部被许可（SA）/网络（403/超时/无出网）/ToS（Census）排除。**"既合规又语义适配"的源目前不存在**（科学家 §3.1）。
2. **人力闸门失败**：v2.5 的 agent 交叉校验口径虽已冻结，但真人气门（真实 PI 最初要求的人标注）已由方案 D 替代；资源侧 2+1 真人留痕阻塞未解除——不过本案的决定性阻塞是**源语义不适配**（换源不解除标注/登记问题，科学家 §1.3.3）。
3. **登记闸门失败**：SciTSR 数据主体未下载、原始文件 sha256 未算（科学家 §1.1、§3.1）。

三闸门均未通过，凑 100 对必然以牺牲语义覆盖/留痕/许可合规为代价，触碰"不伪造来源/哈希/标注记录"红线。

### 1.1 M4 状态定性

- **M4 正式记为「受阻（blocked）」，不是「失败」也不是「未做」**：已尽力执行来源筛选、许可预评估、抓取尝试、语义适配评估，如实记录三重阻塞（许可/网络/人力；其中源语义不适配是决定性因素）。
- **real split = 0**：不生成 `cf_pairs_real.jsonl`、不写 real 条目入 manifest、不启动任何 real run；"已尽力但受网络/许可/标注/语义限制，real=0，外部效度未获真实文档证据支持"在正文如实披露。
- **不无限期阻塞投递**：real=0 不构成投递硬门槛（论文为负面/实证研究，主终点未评估；见 §5）。

### 1.2 低优先级探查（设期限，不阻塞投递）

- **保留一条低优先级探查线索**：科学家 §2.3 的三个方向（CC0 教材/百科式事实文本、CC0 事实型 trivia、其他 PD 政府文本镜像）作为"未来工作"记录，**由真实 PI 在投递后如有资源再启动**，不设本项目内的截止时间、不影响当前投递。
- **明确**：本轮不再投入人日探查新 real 源；禁止为凑数接受语义不合格源（如下条）。

## 2. v2.5 处理：保持冻结、无适用对象

> **裁定：v2.5（agent 交叉校验口径）保持冻结状态，但因 real 数据不存在，当前无适用对象；不得为"用上 v2.5"而接受语义不合格的源。**

- real=0 → 没有需要校验的 real 对 → v2.5 的 `agent_checker_A/B`、`agent_sampling_reviewer`、`automated_agent_crosscheck` 字段无实际填写对象。
- **严禁"为了启用 v2.5 而降低数据源门槛"**：科学家已判定 SciTSR-pd 语义不适配（F2/F3 不可构造），即使 v2.5 校验口径齐备，也不得据此接受不合格源入库——数据源裁定与标注口径裁定相互独立（v2.5 §ingestion_gate、agent_crosscheck_ruling §3）；**数据源不合格时 v2.5 不授权入库**。
- v2.5 作为后续 real 数据的备用口径保留，待（投递后）若获得语义适配的合规源再启用；本轮不改 v2.5。
