## 1. SciTSR-pd 能否支撑 F1–F6 反事实改写

### 1.1 源的本质（决定适配上限）

`rootsautomation/SciTSR-pd` 的元数据 `cc0-1.0`、README 原文明确「CC0 或等效公共领域 dedication、无署名、无商用或衍生限制」（`modelscope_real_source_probe.md §1` 第 17 行）——**许可干净、白名单内**。但探查报告对内容的定性是：**「科学表格结构识别数据，非连续事实句；需评估能否支撑 F1/F3/F6」**（同报告 §1 第 17 行、§2 第 30 行）。

这一内容是判断的关键：SciTSR 的单元是**科学论文的表格**（行列结构 + 单元格短串：数值、方法名、表头标签、少量日期），不是连续的事实陈述句，也不编码「A 属于 B / 允许-禁止」这类可读命题。而协议的反事实最小单元 `u=(q, d_A, d_B, a, b, m)`（`protocol.md §3.1`）要求同一 `q` 下两份**文档**在关键事实位点不同、答案互斥可核验；`d` 需可被学生 Prefill 并以自然语言 `q` 读出答案。表格需先序列化为文本才可作为 `d`，且事实是「(行,列)→值」的结构化绑定，而非句子中的论元关系。**这从根本上限制了需要连续事实句/实体关系的切片**。

另需注意：探查报告只对 README/小文本算了真实 sha256（README 4,136 B），**未下载数据主体**（§1、§3）。故即便语义适配，**五项登记中的「原始文件 sha256」目前为空**，按红线仍不得入库。

### 1.2 逐切片判断

判据口径来自 `protocol.md §3.2`（六类切片语义）与 §4（联合报告、F5 不入翻转分母）。

| 切片 | 判定 | 理由（可追溯） |
|---|---|---|
| **F1 直接事实替换**（负责人/日期/数值/城市，其余恒定） | **部分支撑（有限，仅数值/日期类）** | 表格单元格可做单值替换（如 `0.85`→`0.95`），序列化后位置天然恒定，是其相对优势。但：① 科学表格主要是**数值/方法标签**，人/城市事实罕见，覆盖不了 F1 声明的全部事实类型；② 需把表格线性化为可问答文本并人工确认该单元格是「可核验的单一事实」、A/B 互斥；③ 表格数值常有内部关联（总计/百分比/多列对照），改一格可能引入**第二处语义不一致**——必须做 M1 式「是否引入第二处改动」核验（见 §4）。故只能有限支撑数值类 F1，非连续事实句。 |
| **F2 推理链变化**（中间别名/隶属/比较，答案在另一句段） | **不支撑（需进一步探查才能定论）** | 合成 F2 依赖跨句段的别名/隶属链（如「黑马由组G支持，组G的负责人是李四」→答案在另一句段），测的是「只盯局部答案串」的捷径。SciTSR 表格把关系编码在**行列对齐**中，缺乏「中间别名位于一句段、答案位于另一句段」的叙事链；无法在不重写为 prose 的前提下构造 F2 语义。判定为不支撑；除非另行把表格改写成带别名链的叙述文本——那已属新建构造管线，且不再是 SciTSR 原生内容。 |
| **F3 关系方向 / 否定**（A∈B→B∈A；允许/禁止反转） | **不支撑** | F3 要求可翻转的方向性命题或否定极性。科学测量表是「(行,列)→值」的陈述，**无可翻转的「A 属于 B」方向关系，也无「允许/禁止」极性**；强行把 `A∈B` 改成 `B∈A` 会破坏表格语义（行列互换即改变所指事实），不满足「词重叠但逻辑关系不同且仍可回答」的构造要求。PI 特别关注的 F3：明确不可用。 |
| **F4 干扰与指向**（多相似实体/干扰段落，排除按频率/位置选答案） | **部分支撑（弱）** | 表格天生含大量相似数值/方法名，是天然干扰项，可构造「在多相似单元格中按表头指向取值」的指向任务——这是 SciTSR 相对最可构造的语义切片之一。但：① 协议写的是「干扰**段落**」，表格无段落结构；② 需防止答案可仅靠位置/频率命中（与研究目的相悖，须专门核验）；③ 仍依赖序列化与人工构造。故弱支撑。 |
| **F5 表层等价（负控，同义改写/语序/格式变更，答案不变）** | **部分支撑** | F5 是**非翻转负控**（不入翻转分母，`protocol §3.2`、`v2.4 flip_denominator excludes F5/F6`）。表格对「无关格式变更/语序变化」天然适配：行序/列序重排、表格↔线性文本互转、单元格标签同义替换（值不变）都可直接构造，答案保持 A/B 同一。这是 SciTSR 适配度最高的切片。限制：连续句的同义改写空间有限；行/列位移与 F6 的位置效应重叠，需在构造时分离。 |
| **F6 长度 / 位置控制**（长度匹配 + 不匹配 + 位置移动子集） | **部分支撑（有重要缺陷，PI 关注项）** | 长度：数值替换可做 token 长度匹配（`0.85`→`0.95`）与不匹配（`0.85`→`12.34`）子集。位置：可**整行/整列移动**使目标事实位置改变而内容与其表头绑定不变，形式上支持「位置移动」。但关键缺陷：表格的位置**本身是事实身份的一部分**（行X列Y=值）；仅移动单元格值而保留表头会改变所指事实，与 F6「把位置变化与事实不保真分离」的目的冲突；且合成 F6 是 prose 式「前置说明…负责人是X。补充说明见附件」的 `position_gap` 控制，SciTSR 无此结构。故可部分构造但控制不如 prose 干净。PI 特别关注的 F1/F3/F6：F1 有限、F3 不可用、F6 部分可用但有绑定缺陷。 |

### 1.3 SciTSR-pd 总体判定

**不能作为 M4 的合格 real 改写源。** 理由有三层：

1. **语义覆盖不全**：仅 F1(数值)、F4(弱)、F5、F6(部分) 可有限构造，**F2、F3 不可构造**——而 F1–F4 是语义变化主切片（`protocol §3.2`「F1—F4 采用语义变化成对样本」）。用只能覆盖部分切片的源做 real，会系统性改变任务分布，使 real 与合成任务不可比。
2. **外部效度增益有限甚至反向**：real split 的目的是检验「affine 迁移失败边界」是否在**真实连续文本**上成立（`v2.4 external_anchors.purpose` 同类表述）。科学表格是比合成模板更窄、更结构化的人工域，把它当「真实文档」会把外部效度论证做成「从合成模板换到另一种人工结构」，**不仅不能支撑跨真实文本泛化，反而可能被审稿人指为概念混淆**。
3. **构造与登记成本不低**：需新建「表格序列化→QA 化→候选 A/B→内部一致性核验」管线，且原始文件 sha256 尚未计算（§1.1）；而 M4 的绑定阻塞本就是**人工标注资源**（2 标注 + 1 抽检，`m4_blocker_ruling §1` 阻塞 2），换源并不解除该阻塞。

许可干净（CC0）是 SciTSR 的唯一明确优势，但**「合规」不等于「语义适配」**。

## 2. ModelScope 上是否有其他可用候选

### 2.1 已有探查的结论（不重复、不编造）

`modelscope_real_source_probe.md §1` 已逐一核验，高适配文本源全部出局：`common-pile/public_domain_review`（底层 CC BY-SA，元数据 Apache 冲突）、`wikimedia/wikipedia`（SA）、`AI-ModelScope/wikipedia-cn-...`（cc-by-sa-3.0）、`TeraflopAI/wikicommons-cc-0`（license=other，不清）、`SkyContact/TheCompleteWorksOfLuXun`（文学非事实）、`alfredplpl/...`、`raaa337/...`（图片）、`ZJUNLP/FactCHD`（事实核查非文档事实源）。报告 §2 明确：**「无大量连续事实句的 CC0 文本源被确认」**，唯一 CC0 可下载事实文本候选就是 SciTSR-pd。

### 2.2 判定标准（可作为后续探查的白名单/语义双闸门）

任何新候选须**同时**满足，缺一即排除：

1. **许可原文核验**（非仅元数据）：README/LICENSE 实字节显示 公共领域/CC0/CC BY（无 SA、非仅研究用途、无 ToS 改写冲突）；按探查报告 §2 教训，「Apache 打包层」不得采信，须原文从严。
2. **连续事实句**：含可被单事实编辑、A/B 互斥可核验的连续陈述句，能覆盖 F1–F4 至少多数主切片（尤须能构造 F3 的方向/否定）。
3. **字节可得 + 哈希可算**：能取真实字节流并计算原始文件 sha256（五项登记第④项）；无法取得主体字节者不得入库。
4. **簇规模**：能产出足够多的独立 `source_doc_id` / `real_topic_cluster`，目标 ≥24 簇以满足 v2.4 `min_clusters_for_inference`；不足则 `exploratory=true`。
5. **无个人信息**：含个体标识的句子整批剔除（`m4_compliance_signoff` 待决⑤）。

### 2.3 候选方向（均为「需进一步探查」，本报告不确认其存在/许可/哈希）

- **公共领域/CC0 的教材、百科式事实文本**（如开放教材、政府/public-domain 事实读物的 ModelScope 镜像）：语义上最贴合 F1–F3；但需逐一核验底层许可（很多是 CC BY 或 CC BY-SA，SA 即排除）与是否含个人数据。**需进一步探查**。
- **CC0 的事实型问答/trivia 数据集**：A/B 结构与 `g(C,q)` 口径接近，可能支撑 F1/F4/F5；但需确认是「文档事实编辑」而非「无上下文问答」，且许可为 CC0/PD。**需进一步探查**。
- **其他 .gov / 国际组织公共领域事实文本的 ModelScope 镜像**：Census 已永久剔除，但同类公共领域文本若可下载且非「仅引用」条款，理论上可作源；须避开 ToS 改写冲突与 403。**需进一步探查**。

**预期管理**：因已有探查基本穷尽关键词（cc0 / public domain / wikipedia / 事实 / 百科 / trivia / baike）且高适配源均为 SA，**新候选存在的可能性不高**；上述方向是「探查清单」而非「已确认可用源」。本报告不提供任何数据集存在性断言或哈希值。

## 3. real 目标 100 对是否可达成

### 3.1 判定：**当前条件下不可达成（高质量、可核验、覆盖 F1–F6 的 100 对）**

依据（均为已核验事实，非推断）：
- **语义闸门**：唯一许可干净候选 SciTSR-pd 不支撑 F2/F3、仅有限支撑其余切片（§1.2–1.3）；其余高适配源全部被许可/网络/ToS 排除（§2.1）。即「既合规又语义适配」的源**目前不存在**。
- **资源闸门**：M4 入库的绑定阻塞是人力——需 2 标注者 + 1 抽检员的真实留痕，尚未到位（`m4_blocker_ruling §1` 阻塞 2、§2 结局表）。即使源到位也无法完成双人校验与 ≥20% 抽检（`m4_compliance_signoff §3`）。
- **登记闸门**：SciTSR 数据主体未下载、原始文件 sha256 未计算（`modelscope_real_source_probe.md §1/§3`），五项登记不齐。

三条闸门分别对应 §2.1 的「源」「人力」「登记」，均未通过。凑 100 对必然以牺牲语义覆盖、人工留痕或许可合规为代价，触碰「不伪造来源/哈希/人工记录」红线。

### 3.2 建议：按 PI 预承诺降级路径执行

`m4_blocker_ruling §2` 已给出三结局。基于上述判断：

- **首选：M4 受阻披露（real=0）**。触发条件「ModelScope 无合规源」已实质成立（唯一 CC0 源语义不适配 = 无可用合规源）。在正文/notes 如实写「已尽力但受许可/网络/人力限制，real=0，外部效度未验证」，不无限期阻塞投递。
- **备选：M4 部分/延后**。若真实 PI 出于策略坚持用 SciTSR，则只能生成**暂存于 `reports/_non_authoritative/` 的探索性草稿**（不入库、不进主实验），待人力到位再续；且必须在论文中明确「real 源为科学表格、仅覆盖部分切片、非连续真实文本」，不得称其为外部效度证据。
- **不建议**：为凑数把 SciTSR 当作合格 real 源入库——这会把 §1.3 的三层缺陷带进论文，且不构成有效外部验证。

### 3.3 对论文外部效度论证的影响（不可夸大）

- 按 `v2.4 invariants` 与 `predeclared_interpretation`，real 仅**增强**外部效度、不改变贡献状态（贡献(1)(2) 撤回、(3) withheld 维持）。real=0 → **外部效度未获 real 证据支持**，须在 limitations 明确标注，不得写「跨数据源普遍成立」。
- **锚点通道独立可行**：PI 已实测 SQuAD 官方页 HTTP 200 + 真实字节（`m4_blocker_ruling §0`），SQuAD（主）/ARC（辅）锚点可先行（`§3 4b`），能提供**有限的、标准 QA 域**外部锚点；但锚点是常规 QA 评测，**不等价于真实反事实文档**，不能替代 E4 式泛化证据，也不构成贡献(3)。写作者须把锚点结果按 v2.4 三情形归类，不得反转叙事。
- 净效果：论文仍可作为「失败边界 + 数据泄漏教训」的实证/负面结果研究成立，但**外部效度只能被保守陈述为「在合成域 + 标准 QA 锚点上观察，真实文档外部效度未验证」**。

## 4. 若接受某种 real 源，必须满足的构造约束

> 以下为科学侧最低约束，不替代 SOP/PI 二次签off。若最终选择 real=0，本节不适用。

1. **M1 退化对断言（必须）**：对每个 `must_flip=true` 样本生成后断言 `candidate_A != candidate_B`、`correct_A != correct_B`、`context_A != context_B`；F5 保留相同候选且 `must_flip=false`（非翻转负控，设计使然）。此断言已是合成数据修复项（退化对 18→0，`data_fix_report.md §M1`），real 构造须复用；表格源还须额外核验「单值编辑未引入第二处语义不一致」（§1.2 F1）。
2. **两级隔离（必须）**：以 `source_doc_id`（同一原文，最小不可分簇）+ `real_topic_cluster`（同主题/实体域）两级分组；同一簇不得跨 real 内部评测子集（GroupSplit）。bootstrap 以簇为重采样单位、簇内成对保留；**禁止用逐对唯一 id 充当簇**（v2.4 `cluster_bootstrap_convention`、`m4_compliance_signoff §5`）。簇数 <24 标 `exploratory=true`，附 pair-level 敏感性，不作强推断。
3. **不得污染合成 test（必须）**：real 与合成 test 不得共享 source_doc / 原文哈希 / 逐字 context；real 不并入 test、不参与或重算任何已冻结主终点、CI、flip 口径（v2.4 `forbidden_after_freeze`、`m4_compliance_signoff §5`）。
4. **五项登记 + 二次签off（必须）**：每份来源登记 ①来源 URL/标识 ②版本/日期 ③许可证原文 ④原始文件 sha256 ⑤处理脚本 commit；许可属白名单；再加双人校验、≥20% 分层抽检、PI 最终合规签off，缺一不得入库（`m4_compliance_signoff §3`、`m4_blocker_ruling §1`）。**无原始字节不得计算/编造 sha256**。
5. **五类指标联合报告（必须）**：real 臂 Joint(affine) vs kd_only 两臂，沿用 `E_CF`、τ=1.0、self_threshold=0.1；联合报告 `dual_correct` / `flip_consistency` / `coverage` / `info_attribution` 与 `transfer_broken` 正交字段；≥3 seed（real 臂）、bf16/sdpa、`zero_re_prefill=true`、provenance 齐全、串行（v2.4 `real_split.arms_and_comparison`、`run_discipline`）。
