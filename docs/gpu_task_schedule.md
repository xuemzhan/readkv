# GPU 任务排程与失败重试协议（2×2 补充实验）

> 依据：真实 PI 决策（docs/decisions/human_decisions.md 第 11 项）、PI 裁决 docs/decisions/gpu_supplement_ruling.md、方案 refine-logs/EXPERIMENT_PLAN.md。
> 资源约束：**单卡 RTX 4090 24GB**。实测并发 2–3 任务会使单 run 耗时放大 3–7 倍，**一律串行**；不得并发跑多个 GPU run。

## 1. 任务队列（按依赖顺序）

| 序 | 任务 | 执行方 | GPU | 依赖 | 验收 |
|---|---|---|---|---|---|
| 0 | 冻结 `configs/prereg/gpu_followup_v2.7.yaml` | PI | 否 | 无 | 文件存在且 frozen:true |
| 1 | CPU 导出旧/修复版 6+6 组 train/val + 哈希 + 旧版缺陷统计 | 数据工程师 | 否 | 0（可并行实现） | 6×120 train / 6×60 val，SHA-256 齐全，报告落盘 |
| 2 | 实现独立审计入口（显式接收两份 train/两份 val，不调 P1_gpu.py 自动重建）+ **seed0 冒烟门** | 工程师 | 是（冒烟仅小子集） | 0、1 | 缓存恒等性/输入审计/样本指纹通过；冒烟行标 non-authoritative |
| 3 | seed0 正式 4 格：A00、A11（先），再 A01、A10 | 工程师 | 是 | 2 冒烟门 PASS | 与历史对角格逐对核对；产出 4 格完整指标 |

**总 GPU 预算**：1–2 单卡 GPU 小时（12 格 + 冒烟 + 重试缓冲）；全程串行。

## 2. 失败重试协议（每任务最多 3 次）

1. **每次失败必须留痕**：保存完整 stdout/stderr 日志至 `/tmp/opencode/audit_2x2_<cell>_attempt<N>.log`，记录 run_id、git hash、输入文件 SHA-256、失败时刻与退出码。
2. **分类分析原因**（按优先级排查）：
   - 数据问题：train/val 哈希不匹配、pair_id 跨版本误配、样本数不符、旧版退化对未如实记录；
   - 环境问题：CUDA OOM、显存不足、torch/transformers 版本、dtype/kernel 漂移；
   - 实现问题：审计入口调用了自动重建数据、position offset / de-RoPE / layer_map 错误、zero re-prefill 断言失败；
   - 统计问题：簇数<24 未标 exploratory、bootstrap 口径与 v2.3 冲突；
   - 资源问题：timeout、I/O 错误、磁盘不足。
3. **修复后再试**：每次尝试必须修改一处可识别的原因（代码/配置/环境），不得无改动重试；修复写入新 commit（避免 R1 重演）。
4. **run_id 命名**：正式格 `audit_2x2_A{ij}_s{k}`；重试使用 `audit_2x2_A{ij}_s{k}_try2` / `_try3`，并在索引中标 `superseded=true` 或 `attempt_history`，**不得覆盖或伪造首次尝试产物**。
5. **三次上限**：同一格第 3 次仍失败 → **停止该格**，如实上报 PI（附三次日志与根因分析），不继续重试、不跳过掩盖、不以其他格结果代替；PI 决定是否调整方案或改描述性叙事。
6. **冒烟门失败**：任务 2 冒烟最多 3 次；未通过不得进入正式格。

## 3. 强制提交检查点（真实 PI 追加，2026-11-23）

> **每一个任务/每一格 run 完成后，必须先整理数据并进行 `git commit` + `git push`，确认远程同步后，才能开始下一个任务/下一格。** 防止数据丢失。

1. **检查点粒度**：
   - 任务 1（CPU 数据导出）完成 → 整理并提交推送；
   - 任务 2（入口实现）完成 → 提交推送；冒烟门完成 → 提交推送；
   - 任务 3–5（GPU 正式格）：**每完成 1 格**（A00、A11、A01、A10 × 3 seed 共 12 格）→ 整理该格全部产物（config/manifest/metrics/scores/ledger/日志摘要）→ commit + push → 再进行下一格；
   - 每次失败尝试的日志与根因分析也必须 commit + push（保留失败留痕）；
   - 任务 6–8（统计、补稿、审稿/P5）各阶段完成 → 提交推送。
2. **提交要求**：不得 `git add -A` 盲目提交无关的临时大数据；仅提交当前任务产物与必要的索引/报告更新；提交信息写明任务/run_id/尝试次数；push 后确认 `git status` 干净或仅剩下一任务待办文件。
3. **顺序铁律**：commit+push 未完成前，不启动下一格/下一任务；若 push 失败，先解决推送问题（认证/网络），不得跳过。

## 4. 纪律

- 不并发跑 GPU；不修改已冻结判据（含 v2.3/v2.7）；不改主终点、不恢复贡献；
- 旧版 train/val 只在审计格使用，不进入正式主实验；
- 所有数字转抄冻结产物，不重算已冻结 CI；
- 失败分析以证据为准，不得为"跑通"放宽判据或改数据。
