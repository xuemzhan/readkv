# ReadKV GPU 补充实验方案

**日期：2026-11-23。** 目标是解释 affine 在合成验证集上的结论翻转，把校准语料版本与评估语料版本的影响分开。首轮使用 Qwen3-1.7B→0.6B、严格零重预填充、单卡、三个既定数据 seed。范围为现有的 train/val 和数据审计补实验。

## 1. 首轮必做：校准版本 × 验证版本

| affine 校准语料 | 旧版验证集 | 修复版验证集 |
| --- | --- | --- |
| 旧版 train | A00，复现历史对角格 | A01，固定修复版 val，比较 A11 |
| 修复版 train | A10，固定旧版 val，比较 A00 | A11，复现修复版对角格 |

每个 seed 各有 120 个校准对和 60 个验证对。两个 affine mapper 各拟合一次，再各自评估两个 val。三个 seed 共 6 次拟合、12 个评估格。四格统一运行环境和评测入口。冻结两端模型及 tokenizer 的 revision，记录权重文件指纹、运行代码提交和软件版本。沿用 BF16/SDPA、等深层映射、逐层逐头 K/V affine、ridge λ=0.001 和历史首 token 评分。按版本和 seed 固定用于拟合的原始文档与顺序，记录各版本实际校准 token 数。Joint 推理每次只接收查询与目标缓存。记录实际送入模型的输入长度，核验严格零重预填充。

**数据准备。** 旧版取 `458de18` 生成器，修复版取 `efc3ba3` 生成器。在 CPU 侧各导出 seed 0/1/2 的 train 与 val，生成时设置其他 split 为 0。已验证这个配置的 6 组 train 各有 120/120 对与原规模生成一致，6 组 val 各有 60/60 对与归档 Joint 行中的样本哈希一致。写入分别对应每个版本、split、seed 的规范 LF SHA-256，并用版本与样本文本哈希标识每条记录，避免同名 pair ID 跨版本误配。在旧版诊断格记录重复文本、候选退化及实际 train–val 重叠。保留旧格的历史样本，才能核对历史结果及评估集变化。

**工程入口。** 现有 `P1_gpu.py` 由同一生成器取 train/val，`run_cf_pipeline` 还会自动重建数据并执行质量门。为补实验实现一个独立审计入口，显式接收两份 train 和两份 val，调用现有 GPU 后端、affine 拟合、打分和日志写入。旧数据的历史缺陷应由审计入口按格登记。正式流程的质量门继续生效。固定每个 val 内的查询、金标签、候选 token、样本顺序及对照选择，同一 val 的 Self/Identity 可以复用。复现历史对角格时沿用原错配选择；错配策略本身的稳健性可另列。每格保存配置、样本指纹、逐对各臂分数、审计告警及耗时。

## 2. 指标和结果判读

定义 `L = Self 双侧正确率 − Joint 双侧正确率`，单位百分点。主表使用全部 60 对的 L 对接历史翻转，同时显示 Self 和 Joint 原值。四格分 seed 报告。预先固定两项关键对比：

| 对比 | 计算 | 支持的解释 |
| --- | --- | --- |
| 固定验证集，换校准语料 | 旧 val 上 A10−A00；修复版 val 上 A11−A01 | 同一批样本上，校准语料版本如何改变 affine 迁移。 |
| 固定 mapper，换验证集 | 旧校准下 A01−A00；修复版校准下 A11−A10 | 同一 mapper 在两套不同验证样本上的表现差异，包含任务组成、实体、标签及难度的变化。 |

同一验证集按样本配对、按模板族重采样 10,000 次，逐对区间作为敏感性分析。估计两个固定验证集上的校准效应之差，查看校准与评估语料是否存在交互。跨版本验证集比较按不同样本集处理，即使两边 ID 字符串相同。三组 seed 分开报告，逐 seed 保留各自模板族计数。少于 24 个模板族时标为探索性，可附逐族留一结果。历史 20 点阈值作为图表参考。

预设敏感性报告包括 F1–F4 的双侧正确率、剔除各自 val 中两个候选相同样本后的结果，以及 F6 的单独结果。次指标为 Joint E_CF、基于 F1–F4 且 |D_self| > 0.1 的方向一致率与分母、coverage，以及同一验证集的控制结果。联合报告 E_CF 与双侧正确率。

- 固定 val 更换校准语料后差异持续，稿件可以报告该校准版本在这些样本上的影响。
- 固定 mapper 更换 val 后变化更大，稿件应强调迁移判断对评估样本构成的敏感性。
- 两种换法都改变结果，或方向依赖 seed 和验证集，报告四格和交互，保留混合解释。
- 四格识别的是两个数据版本整体切换的影响。若要把变化归因于去重、退化样本或模板重叠中的某一项，需单独干预该项。新增未见模板主要位于 probe/test，无法用当前 val 对照推断这项改动的效果。

## 3. 执行顺序和资源

| 阶段 | 批次 | 验收与后续动作 |
| --- | --- | --- |
| CPU 准备 | 6 组 train、6 组 val | 样本数、身份、重叠清单和哈希核对齐全；固定指标口径并提交补实验入口。 |
| GPU 冒烟 | 先做 seed 0 的缓存恒等性检查，再用每个 val 的固定小子集走四格 | 同一 val 的 Self/Identity 等于约定数值容差内的锚点；Joint 输入审计通过；同一 val 两个 mapper 的样本与控制一致。冒烟行单独归档。 |
| seed 0 全量 | A00、A11，再 A01、A10 | 对角格与历史逐对结果核对。先排查样本、checkpoint/依赖、logit 和 gold 读数差异。若快照无法追溯，把新对角格视为统一环境复验，并注明其与历史运行的差异。 |
| seed 1、2 全量 | 每个 seed 4 格，共 8 格 | seed 0 技术门通过后完成其余种子。方向一致、接近零和方向异质的结果都按四格报告。 |
| 汇总 | 对角格核对表、四格主表、逐 seed 配对差图 | 将可复核的数据版本结论写入主文。交互、分切片和控制分析进补充材料。 |

归档 RTX 4090 上，六次旧/新 affine 单次记录为 172–440 秒。按 12 个格各独立运行估算约 35–90 分钟。首轮建议预留 **1–2 单卡 GPU 小时**，包含冒烟和排查缓冲。当前卡型、显存、复用比例和 I/O 会改变耗时，用 seed 0 实测更新预算。按单卡串行排程即可。现有模型对足够支撑首轮。

## 4. 首轮后的资源投向

**候选整串评分是优先的稳健性补充。** 若保持论文为描述性失败边界案例，在同一批修复版 val、同一 affine mapper 上，对 Self/Joint 比较历史首 token 与两个候选的完整条件序列对数概率。重新前向时让两个候选从同一原始缓存分支，以 teacher forcing 计算候选 token 的 logprob 之和，核对 query–candidate 的 token 边界，并固定 EOS 和长度处理规则。另列按 token 数归一的敏感性分析。先跑 seed 0 核对评分和开销，再按相同设定完成 seed 1、2。历史日志只有首 token 读数，因此这一步属于新增模型前向。若 affine 的失败定性依赖读数选择，正文把结论限定到相应读数。

**单缺陷因果实验留给明确的论文主张。** 如果要声称某项缺陷本身造成翻转，在固定修复版 val 上比较相同大小、模板与 token 预算尽量匹配的校准组，只改变指定缺陷。以精确重叠为例，预先固定若干 train 槽位，将匹配的非重叠文档替换为对应 val 文档，记录重叠剂量与来源，并在同一个 val 上报告两组配对差。这个干预估计的是指定注入方式下的精确重叠效应。若四格结果已经足以支撑论文采用的数据版本描述，GPU 可优先用于候选整串核验，首轮依然限定在一个模型对。
