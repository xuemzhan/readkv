# ReadKV GPU 实验方案：完整候选答案评分

**2026-11-24。** 本实验检验两个结论对评分方式的敏感性：修复版 A11 的 affine 迁移失败，以及 A00 到 A11 的历史翻转。当前 v2.7 将整串评分列为投稿后补充，本方案沿用这一排期。结果适用于 Qwen3-1.7B→0.6B、既有合成验证集和采用 affine 的严格零重预填充设置。

## 1. 实验矩阵

| 优先级 | 运行 | 校准 / 验证 | 用途 |
| --- | --- | --- | --- |
| 1 | seed 0 的 A00、A11 固定小样本 | 旧 / 旧，修复 / 修复 | 冒烟，验证历史首 token 一致、候选之间缓存隔离、位置和零重预填充。 |
| 2 | seed 0 的 A00、A11 各 60 对 | 同上 | 完整试运行，测耗时和显存，核对首 token 对角格。 |
| 3 | seed 1、2 的 A00、A11 各 60 对 | 同上 | 按固定参数完成其余四格。六格均进入结果表。 |
| 可选 | A01、A10 × seed 0/1/2 | 旧 / 修复，修复 / 旧 | 仅当论文要讨论校准/验证版本分解本身对整串评分是否稳健时增加。 |

正式首轮共 6 个评估格。每格的同一批样本同时给出首 token 和整串读数，对 Self、Joint 各自评估文档 A/B 两侧。Identity 用于冒烟锚点。固定旧/修复版 train、val 的逐 seed 文件及规范 LF SHA-256，不评估封存 test。

主分析用 F1–F4 中候选文本不同、两侧金标签确实在 A/B 之间交换的样本。CPU 已核对每版每 seed 共有 60 对，其中 F1–F4 有 46 对。主分析旧版为 **42/42/41** 对，修复版为 **46/46/46** 对，每格 6 个模板族。另报全部 60 对以对齐旧表，单列 F5、F6 和相同候选。两种评分始终使用同一格内相同的样本集合。旧版与修复版是两套验证样本。

## 2. 固定的实现和评分口径

1. **冻结模型与输入。** 沿用 28→28 等深映射、逐层逐头 K/V affine、ridge λ=0.001、BF16、SDPA。每格只拟合一次，同一 mapper 服务两个评分口径。记录实际 checkpoint、tokenizer、权重文件指纹、代码 commit、远端依赖和设备信息。旧跑分只记了可变的 snapshot 别名时，用首 token 逐对一致性确认数值复现，并注明可核验的身份范围。
2. **复用现有缓存路径。** 独立入口复用现有数据导出、闭式拟合与缓存构造。对 Self 和 Joint 保持相同的历史查询 token 序列。分别从同一文档缓存新建候选 A、B 的可变学生缓存。先前向 query 得到首 token 分布，再依次喂入该候选的真实前缀 token，累加目标 token 的 logprob。保留相同位置偏移，后续每次位置加一。现有 `inject_and_generate(max_new_tokens=...)` 走贪心解码，因此 teacher-forcing 需要单独的入口或显式评分模式。
3. **固定 token 边界。** 主口径使用历史查询 token 加原先独立 tokenize 的候选 token，二者都关闭自动特殊 token，首位评分对象与归档相同。检查 `encode(query + candidate)` 与两个 token 序列拼接是否一致，记录不一致和候选互为前缀的样本数。主口径解释为该固定 token 序列的条件概率。若边界不一致较多，另用固定答案分隔符做边界敏感性，两个读数使用同一个新前缀，单列结果。
4. **记录三个评分。** 首 token 取第一项 logprob，用于历史回放。整串评分是各候选 token 的条件 logprob 之和，用 FP32 做 log-softmax 与求和，固定不追加 EOS。长度敏感性用总和除以候选 token 数。三者采用同一候选和 gold，精确同分时沿用归档的固定候选顺序，并报告同分数。记录候选 token 长度、首 token 冲突与全序列同分，便于判断长度和词元切分的影响。
5. **逐次审计。** 每条候选分支记录实际输入 token id 或其指纹、位置和每次 forward 长度。对长度为 m 的候选，实际学生输入长度序列应是 `[Q, 1 × (m−1)]`，其中 Q 为原查询长度。只有查询和当前候选前缀进入学生的显式输入；文档长度只体现在注入的缓存及位置偏移。断言候选缓存相互独立，任何审计失败应中止该格并保留失败信息。

## 3. 技术验收与判读规则

**冒烟验收**

- 首 token 路径能重现工作树中同输入的旧打分。用单 token 候选核验整串与首 token 一致，用多 token 候选核验 teacher forcing 的分数位置。交换 A/B 前向顺序后，按候选身份比较，分数保持一致。
- Self 与 Identity 的 gold 判定和分数差在预先记录的数值容差内。逐次学生输入审计全部通过，两个候选都从同一初始状态独立开始。
- seed 0 两个全量格对齐归档首 token 的样本身份、逐对 Self/Joint margin 和 dual。记录每一处差异。遇到无法解释的差异，先核对 checkpoint、token 边界、精度和缓存位置，暂停扩展。若旧快照身份无法恢复，可以记录为统一环境的成对敏感性分析，但须明示与归档的差异。
- 技术门通过后完成三个 seed。正式矩阵的扩展依据是技术可比性，结果方向和幅度全量报告。

**主指标与统计**

- 每格、每种评分分别报 Self、Joint 双侧正确率及 **L = Self−Joint**，单位为百分点。分别报告 `L_full − L_first`。同一格内这两项用同一批样本，按配对差重采样模板族 10,000 次，同时给逐对敏感性。
- 每个 seed 分别报告 **A11−A00 的 L 差**，并报告整串与首 token 下这项差的变化。为了比较评分方式，先在各自验证集内计算配对的 `full−first`，再对两版本的这个差做独立模板族重采样。每次重采样的统计量为抽中样本之和除以抽中样本数，与按样本加权点估计一致。
- 次指标报 E_CF、方向一致率及实际分母。方向一致率在各评分的 Self 合格集报告，同时在两种评分共同合格的样本上做敏感性分析。E_CF 计算在各自评分方式内进行，完整候选求和和首 token 的绝对误差尺度可能不同。用于描述失败的历史 20 点线仅作参照。每 seed 独立报告，每格 6 或 8 个模板族的区间均标探索性。

**论文判读**

- 若三组 A11 的整串 L 仍为正，且 A11−A00 的方向与首 token 一致，可写成「在两种候选评分下，观察到相同的点估计方向」，并报告幅度及区间。分别标出跨过历史 20 点参考线的 seed。区间用于展示不确定性。
- 若 A11 的下降明显缩小、某些 seed 方向改变或 A11−A00 的差消失，论文应明确失败或翻转结论对首 token 评分敏感。若按长度归一后判读改变，分别报告总 logprob 与归一结果。
- 只跑 A00/A11 支持对角翻转和 A11 失败边界的评分稳健性。如需讨论 2×2 的交互本身，再等量补 A01/A10。该题的结论限于评分方式，不涉及单项数据缺陷的因果归因。

## 4. GPU 预算与产物

旧版 2×2 的 A00/A11 六个首 token 格在归档中每格 108–135 秒。整串需要额外前向，耗时取决于候选 token 长度、缓存分支和本机 I/O。按单张已有 GPU 先留 **30 分钟**做冒烟与 seed 0 两个全量格的上机窗口。整个六格先按 **0.5–1 GPU 小时**调度，这是占卡预算。以 seed 0 实测的每格耗时、每候选 token 数和显存峰值更新剩余预算。若只能排到一格，先跑 A11 seed 0，它只回答修复版上的失败是否对评分方式敏感。

每格使用新的 run ID，保存 `config.json`、`scores.jsonl`、`forward_audit.jsonl`、`metrics.json` 和 `manifest.json`。逐对日志包括样本指纹、校准与验证版本、双侧两候选的三种分数、gold、预测、模板族、token 长度和失败标记。最终产物是一张逐 seed 的首 token/整串对照表、归一敏感性表，以及历史回放和输入审计摘要。原始 2×2 运行继续作为历史归档。
