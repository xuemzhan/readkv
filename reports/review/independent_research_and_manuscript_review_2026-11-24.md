## 1. 实验核查与新的科学判断

四格均有 60 对 × 8 臂。复核全部 5,760 行，12 格与各自验证集的样本身份均吻合，包括同一验证集固定 Self 的要求。按 LF 规范化核对的 48 个输入哈希引用、36 个运行文件哈希均匹配。12 格 Self 和 Identity 的双侧正确、分数差及误差逐对一致。复算的 12 个模板族主区间、12 个逐对敏感性区间、12 个 Joint E_CF 模板族区间、6 个固定 val 的配对对比均与归档一致。6 个对角格的 Joint E_CF 和 Joint dual 各 360/360 项逐对等值。这个复现结论专指相应的结果与臂。历史错配与随机对照的策略在新代码中有变，跨批次对角格匹配分别只有 71/360 和 158/360 条 E_CF。 [正式运行汇总](../audit_2x2_formal_summary.json) · [模板族统计](../audit_2x2_l_ci.json) · [审计入口](../../experiments/audit_2x2_gpu.py)

### 1.1 四格结果支持怎样的主张

表内每项为 **Self → Joint（L）**，单位为百分点。A00/A10 用旧 val，A01/A11 用修复版 val。L 为 Self 减 Joint。

| 校准/验证 | seed 0 | seed 1 | seed 2 |
| --- | ---: | ---: | ---: |
| A00 旧/旧 | 68.3 → 66.7（+1.7） | 60.0 → 65.0（−5.0） | 65.0 → 61.7（+3.3） |
| A01 旧/修复 | 81.7 → 55.0（+26.7） | 90.0 → 61.7（+28.3） | 78.3 → 45.0（+33.3） |
| A10 修复/旧 | 68.3 → 30.0（+38.3） | 60.0 → 36.7（+23.3） | 65.0 → 40.0（+25.0） |
| A11 修复/修复 | 81.7 → 41.7（+40.0） | 90.0 → 28.3（+61.7） | 78.3 → 38.3（+40.0） |

- **固定旧验证集换校准语料**，L 增加 36.7、28.3、21.7 点，模板族区间下界为 15.5、13.8、0.0 点。固定修复版验证集的增加为 13.3、33.3、6.7 点，三组中只有 seed 1 的探索性区间下界大于零。这两组对比固定了 Self，因此直接对应 Joint 表现变化。
- **固定 mapper 换验证集**，L 的点估计也都增加，但 Self 同时改变。最直观的是修复版校准的 seed 0：A10→A11，Joint 从 30.0% 上升到 41.7%，Self 从 68.3% 上升到 81.7%，所以 L 仍增加 1.7 点。论文应展示 Self 和 Joint 两个水平，避免把参考差扩大一概解释为 Joint 变差。
- **交互量**采用 `(A11−A01)−(A10−A00)`。我按固定 val 内配对、两个验证版本独立重采样模板族，按样本数加权，使用 10,000 次抽样，得 **−23.3 [−47.6, 3.4]、+5.0 [−22.9, 31.0]、−15.0 [−44.0, 16.1]** 点。点估计方向有异质性，三个探索性区间均覆盖零。可沿用 v2.7 的内部混合判读，论文应写成“两种版本切换均改变点估计，交互方向未稳定”。单个对比区间是否覆盖零，无法替代交互估计。
- **敏感性**支持核心定性。只取 F1–F4 后，A00 三组 L 为 0.0、−6.5、4.3 点，其余九格为 **23.9–65.2** 点。剔除候选文本相同的样本后，A00 为 2.0、−6.1、4.2 点，其余九格为 **28.6–69.8** 点。两组敏感性说明，与旧对角格的差异在这些重算口径下仍在。它们无法量化退化样本、去重、模板重叠中单项因素的影响。

这个案例最有说服力的结论是：**对同一模型对、affine 实现和首 token 测量，历史旧/旧条件下 Self 与 Joint 的差较小，使用修复版校准或验证语料的全部九格都出现明显的正向 L 点估计。** 合成验证集每版本仅 8 个模板族，历史 20 点线应保留为描述性参照。留出测试集与原方法主终点维持未评估。 [预先记录的 v2.7 方案](../../configs/prereg/gpu_followup_v2.7.yaml) · [原统计解读](../../docs/audit_2x2_statistical_interpretation.md)

### 1.2 跨验证集区间混用了权重

`audit_2x2_ci.py` 的点估计对样本等权，即按 60 对取平均。跨验证集的 bootstrap 先算每个模板族的均值，再对抽中的族等权平均。实际两版本各有四个 8 样本族、四个 7 样本族。以 seed 0 的 A01−A00 为例，按样本加权点差为 25.0 点，按族等权点差为 23.2 点。我独立复现了现有六份区间，也用与点估计一致的族总和除以抽中样本总数口径重算。两版本独立抽样，以 8+8 族表述其结构。

| 对比 | seed | 归档主区间（族等权） | 与点估计同权重的区间 |
| --- | ---: | ---: | ---: |
| A01−A00 | 0 | [−2.46, 46.21] | [−1.53, 47.54] |
| A01−A00 | 1 | [10.49, 54.69] | [10.40, 55.54] |
| A01−A00 | 2 | [6.69, 51.56] | [7.01, 51.67] |
| A11−A10 | 0 | [−29.24, 31.70] | [−28.66, 32.23] |
| A11−A10 | 1 | [10.27, 64.73] | [10.44, 64.48] |
| A11−A10 | 2 | [−12.72, 43.75] | [−13.15, 44.01] |

区间跨零的分类保持一致，所以这是必须修正的估计口径问题，核心定性保持。论文应采用统一的样本加权口径。族等权估计可作为另一项敏感性分析，并同时给相应点差。当前三个 seed 的 A01−A00 区间有 1 个跨零，A11−A10 有 2 个，合计 **3/6**，正文的“in most seeds”应改为明确计数。四种预定对比 × 三个 seed 共 **12** 个正点估计，正文和签核中的“nine contrasts”混淆了九个含修复版数据的单格和十二项对比。 [CI 实现](../../scripts/audit_2x2_ci.py)

## 2. 必须修订的稿件问题

### 2.1 更新标题、摘要、结果表与投稿信

长稿结果节已撤下多处单缺陷强归因措辞。这项改动应贯穿整份材料。当前标题仍称 “Data Defects Reverse a Reported Finding”，投稿信称原机制和 gap 被追溯到具体缺陷并同时消失，正文也写清洁数据下机制不可复现。正式清洁 P2 缺席，证据支持**撤回旧机制证据**，机制是否在清洁语料中存在保持未决。摘要宜用一个句子报告新增四格的发现，以“reversal after corpus reconstruction”描述观察，把两种版本变化写清楚。同时区分事先冻结的 v2.7 交叉实验与原结果出现后形成的审计研究问题。 [长稿](../../papers/readkv_v2_draft/main.tex) · [投稿信](../../papers/readkv_v2_draft/cover_letter.md)

2×2 表注第 722–723 行把 A01 与 A10 的验证集写反。应改为 **A00/A10 用旧 val，A01/A11 用修复版 val**，保留第 745 行已经更正的对比文字。主表按 v2.7 显示 Self 和 Joint，附四项对比区间、交互量和三项预列敏感性。稿件把这些材料指向 supplement，版本库未见一份可供读者直接阅读的独立补充材料。建议把它们放入匿名 PDF 附录并附可执行复算入口。`scripts/audit_2x2_ci.py` 当前把输入根硬编码为 `/root/readkv`，`--out` 只控制输出。可在修订时增加根路径参数或由脚本位置定位仓库。 [长稿 2×2 结果](../../papers/readkv_v2_draft/main.tex) · [v2.7 分析约定](../../configs/prereg/gpu_followup_v2.7.yaml)

### 2.2 原审稿的指标问题仍在

- **flip 和评分对象。** 正文仍同时把 398 写为语料级计数、声称排除 F5/F6，并报告包含合格 F6 的历史指标。应明确总库计数、验证格候选分母和 Self 阈值后的分母。举例，A11 三组重新按 F1–F4 得 **34/45、35/46、34/46**。第 4 节的概率符号应明确指候选首 token 的二选一代理，F5 的相同候选导致此读数下误差为零和双侧正确率为 1，F6 实际变更了姓名和金标签。候选全文评分可作为后续稳健性实验。当前论文若限定在首 token 代理，现有结果可支撑复审。 [指标实现](../../src/readkv/evaluate/counterfactual.py) · [生成器](../../src/readkv/data/build_cf_pairs.py)
- **KD 效用保持。** 摘要和投稿信仍写 “preserves utility”。KD 全切片的 dual 点差为 11.7、16.7、1.7 点。前两组按模板族的探索性区间均包含 20 点。仅计 F1–F4 时，seed 1 点差为 **21.7 点**。建议写 KD 在全切片聚合下与 Self 的正确率差较小，点差对切片定义敏感。术语 “matched” 应说明匹配了样本和模型配置，计算设置不同。闭式 affine 也从校准语料估计约 740 万矩阵与截距系数，稿件的 “0 parameters” 应改为零个梯度优化 epoch。首 token 层面的 E_CF 为非负绝对差，Self 的零值由定义给出，区间排除零不能单独论证实质效用—保真分离。 [首轮复算](independent_research_and_manuscript_review_2026-11-23.md) · [affine 拟合实现](../../src/readkv/mapper/representation.py)
- **SQuAD 锚点。** 现代码仍取文件顺序前 240 个可回答问题，只覆盖两篇文章，并使用首个参考答案。现表应明确标为单参考子集，或公布按官方全参考口径从现有预测重算的分数（Self/affine Joint/KD Joint 的 F1 约 **0.2178/0.0082/0.0014**，EM 仍为零）。将 “replicates” 限定为这个例集上的描述性下降，“because the base model is not SQuAD-tuned” 缺少对照支撑。 [锚点代码](../../experiments/anchor_squad_gpu.py) · [官方评分脚本](https://github.com/rajpurkar/SQuAD-explorer/blob/master/evaluate-v2.0.py)

## 3. 溯源与执行偏差

- v2.7 在正式运行提交之前已出现在 Git 历史里。输入溯源已显著改善，旧 S1 勘误则仍把 seed 0 导出 SHA 写成所有 clean P1 实际读取文件。应引用逐 seed 新归档证据并更正旧 S1 的适用范围。12 个新 run 的配置含数据指纹和 28→28 层映射，缺少显式的 teacher/student 实际路径、权重和 tokenizer revision/文件散列。入口允许覆盖模型路径。同为等深只能约束结构，脚本的 inferred-model-pair 通过状态应读为配置推断。历史对角的精确复验是强交叉证据，仍建议补当时的快照或远程命令存档，并区分历史实测、事后补录和当前快照。 [正式运行示例](../runs/audit_2x2_A00_s0/config.json) · [原数据勘误](../data_hash_binding_erratum.json) · [一致性修复说明](../consistency_field_fix_report.md)
- 预定每 seed 每版拟合一次，共 6 次，但实际单格入口各自拟合，共 12 次，未见 mapper 工件散列证明同一校准版本的两次拟合逐系数相等。当前证据可报告相同输入、算法与超参数下的闭式重拟合。另有两个冒烟格 A00/A10，冻结文本要求四格冒烟。应披露这个差异及后来正式格上的一致性核对。 [v2.7 执行计划](../../configs/prereg/gpu_followup_v2.7.yaml) · [冒烟日志摘要](../audit_2x2_smoke_report.md)
- 审计入口只对每格首对的一侧额外调用输入检查，保存布尔值，未保存全格逐次的查询与前向长度。运行不通过时当前会写告警，顶层仍写 `zero_re_prefill=true`。所有逐对评分的调用路径支持只传查询的设计，并且归档首样本检查通过。证据强度应如实按代码路径和抽检陈述。若远程仍有细粒度日志，可补归档。若论文坚持声称逐样本审计，需另提供该级别的证据。 [GPU 审计入口](../../experiments/audit_2x2_gpu.py) · [GPU 候选评分](../../src/readkv/models/gpu_backend.py)
- Windows CPU 本机测试 **57 通过、1 失败**。新增的一致性测试通过，失败仍是已有的 Qwen3 缓存恒等性测试，现场 Transformer 接口期待 `past_key_values`，本项目传入 `cache`，出现 layer 0 未持有 K/V。与远端使用的依赖版本区分报告。该结果未推翻已归档的 GPU 对角输出吻合。 [缓存实现](../../src/readkv/models/hooks.py) · [归档环境](../environment.json)
